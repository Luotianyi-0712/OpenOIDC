# Announcements

Open **Admin > Announcements** (`/admin/announcements`) to create, edit,
publish, withdraw, and delete announcements. New announcements are drafts
until **Published** is checked or the publish action is used in the list.
Only administrators can manage announcements; published content is public.

## Display Modes

- **Top banner**: the title appears above the navigation. Clicking the title
  opens the complete Markdown content. Optional dismissal and horizontal
  scrolling apply to this banner. Multiple banners can be navigated with the
  previous/next arrows; the most recently updated announcement appears first.
- **Notification window**: the announcement appears in the bell menu at the
  upper right. Unread announcements show a red dot. Open an item to read it,
  or use the mark-all-read action.
- **Both**: display the same announcement in both locations.

The banner adjusts page spacing rather than covering content. Scrolling only
runs when the title overflows, pauses on hover/focus, provides a pause button,
and respects the operating system's reduced-motion preference.

Markdown supports headings, emphasis, lists, links, images, tables, and fenced
code blocks. The editor provides a preview. Raw HTML is disabled and rendered
output is sanitized with DOMPurify; scripts and unsafe link protocols are not
allowed. Titles are limited to 160 characters and content to 64 KiB.

## Updates and Persistence

The public list refreshes on page load, when returning to a visible tab, and
every minute while the tab is visible. Withdrawing or deleting an announcement
removes it on the next refresh. Open the bell to request an immediate refresh.

Read and dismissed states are stored in browser local storage, separately for
each signed-in account and for guests. They survive reloads and synchronize
between tabs on the same browser. They are not synchronized across devices.
Saving a new revision makes the announcement unread again and restores its
banner, including for people who dismissed the previous revision.

## Storage and API

Announcements use a dedicated `announcements` table. SQLite creates it through
the existing startup migration path; PostgreSQL applies migration `000012`.
No manual schema command is needed.

- `GET /api/v1/announcements`: published announcements only, no authentication.
- `GET /api/v1/admin/announcements`: includes drafts, admin session required.
- `POST /api/v1/admin/announcements`: create.
- `PUT /api/v1/admin/announcements/{id}`: update or change published state.
- `DELETE /api/v1/admin/announcements/{id}`: delete.

Write bodies contain `title`, `content`, `display_mode` (`banner`, `modal`,
or `both`), `dismissible`, `scrolling`, and `is_published`. IDs, revisions,
and timestamps are generated by the server. Management actions are audited.

## Verification

`go test ./...` covers routing permissions, validation, draft isolation,
publication, withdrawal, deletion, revision changes, and SQLite persistence.

From `frontend`, run `npm run build` and `npm run test:e2e`. For a new checkout,
install the browser with `npx playwright install chromium`. The browser tests
use mocked API responses and cover desktop/mobile rendering, Markdown safety,
the editor workflow, unread/dismissed state, account separation, and failures.
